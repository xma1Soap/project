# New API 接入闸门

本文档是收到站长源码后的接入清单。在证据未填完前，所有生产能力必须保持 `false`。

已收到的定制 `v8.13` 快照审查结果见 `SOURCE_REVIEW_V8.13.md`；机器可读的能力声明见
`examples/newapi-contract.v8.13.json`。

## 已完成的通用层

- 额度错误连续阈值和时间窗口；
- 渠道+模型粒度的状态所有权；
- 人工禁用保护；
- 按时区的每日重置和恢复探测；
- 逻辑模型池聚合与最小备用路由保护；
- dry-run、双重 live 开关、单实例锁和审计日志。

## 待实现的版本适配层

只在站长的实际部署版本中确认下列行为：

1. 渠道详情字段如何转换为 `ChannelSnapshot`；
2. 修改整个渠道状态时是否同步 Ability、数据库与缓存；
3. 是否存在安全的“单渠道+单模型”摘除接口；
4. 测试接口是否真的固定渠道和模型，而不会改走其他路由；
5. 错误日志能否按渠道、模型和时间过滤，以及分页是否稳定；
6. 身份验证方式和最小管理员权限。

将结论和脱敏证据填入 `examples/newapi-contract.pending.json`。只有某项已通过源码、测试实例和变更后回读验证，才能将对应能力改为 `true`。

## 实现位置

`newapi_adapter.py` 已定义 `NewApiBackend` 边界。后续只需增加一个具体后端，处理 HTTP
路径、认证、字段映射、分页和缓存同步。控制策略不需要重写。

适配器禁止将“不支持单模型摘除”悄悄降级为“关闭整个渠道”。能力不足时必须显式拒绝。

## 上线顺序

1. 本地固定样例测试；
2. 测试实例只读查询；
3. 测试实例单路由写入与回滚；
4. 主站旁路 dry-run，只记录 `would_disable` / `would_enable`；
5. 只选一个有备用路由的低风险模型池灰度；
6. 确认审计、告警、手动接管和回滚后再扩大。
